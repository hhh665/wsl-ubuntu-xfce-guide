## 过程与修正

| 阶段 | 发生了什么 | 有效处理 / 教训 |
|---|---|---|
| 发现环境 | 工具账户列出“没有发行版”，用户说已经有 Ubuntu | 切到实际 Windows 用户后找到了已有 Ubuntu；没有另装一套 |
| 方案选择 | 用户明确需要完整桌面 | 安装 Xfce，用 WSLg + Xephyr 展示整个桌面 |
| Xfce 空窗口 | 会话 `DISPLAY=:1`，子组件却连 wayland-0 | 加 `GDK_BACKEND=x11`、X11 会话类型和独立 D-Bus |
| 第一次错误验收 | Linux 内部截屏正常，就宣布可用 | 用户实际 Windows 看不到窗口；内部像素不等于 Windows 输出 |
| 第二次错误验收 | 发现进程和窗口在后台，恢复前台 API 返回成功 | 用户仍看不到；这只验证了窗口状态，没有验证合成后的画面 |
| 找到显示根因 | 用户照片出现 `[WARN:COPY MODE]`，实际屏幕中 RAIL 窗口不可见 | 日志确认共享内存分配 EIO、最新 use_gfxredir=0；与 WSLg #1456 相符 |
| 恢复画面 | 仅重启 Weston，最新 use_gfxredir 变为 1 | Windows 屏幕实际出现中文 Xfce 桌面 |
| 输入仍失败 | 用户确认“能看到，但操作没有反应” | 在健康图形通道下重新创建桌面；保留等待和 no-host-grab；用户随后确认“有反应了” |
| 终端目录 | 面板继承了 Windows 下项目目录 | 桌面先 cd HOME，默认终端加明确工作目录；读到终端 shell cwd 为家目录 |
| 安装 Chrome | 官方包下载完成，但 APT 被自动更新占用 | 确认仅卡在 HTTP 下载且没有 dpkg 后，受控结束这次更新下载，未禁用未来更新 |
| Chrome 假失败 | 验证只匹配 Google-chrome，并在短命脚本中后台启动 | 实际类名是 Google-chrome-stable；保留前台 WSL 调用后实际显示浏览器窗口 |

## 哪些推断不能升级为事实

- 不能说所有 COPY MODE 都一定由同一个上游缺陷导致。这里的版本、错误和恢复结果相互吻合。
- 不能说“等两秒”单独解决了所有输入故障。现场还重新创建了桌面会话，并保留了 no-host-grab。
- 不能说 Chrome 首次退出一定是显卡驱动错误。短命 WSL 调用结束与错误出现时间重合，保持应用生命周期后窗口可用。
- 不能说项目里的参数化安装程序已在全新机器端到端验证。现场验证的是原始流程；通用化部分另有自动检查记录。
